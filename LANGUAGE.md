# Поддерживаемый язык запросов

SQL2Py принимает один запрос SELECT к одной таблице. Формальная
[грамматика в EBNF](grammar/sql.g) определяет порядок частей запроса.
Квадратные скобки обозначают необязательную часть, фигурные скобки — повторение.

Ключевые слова и имена сопоставляются без учёта регистра. Имя без кавычек
начинается с латинской буквы или подчёркивания и может содержать цифры
в следующих позициях. Двойные кавычки позволяют писать имена с пробелами,
кириллицей или ключевыми словами. Кавычка внутри такого имени удваивается.
В строковых литералах используются одинарные кавычки, например
`'О''Брайен'`. Поддерживаются комментарии `--` до конца строки и невложенные
комментарии `/* ... */`. Числовой литерал допускает знак, десятичную точку
и экспоненту, а `LIMIT` принимает только цифры.

## Чтение данных

Входные файлы читаются как UTF-8 с необязательным BOM. Таблица представляется
как список строк, где строка хранится в словаре. Имена столбцов внутри
нормализуются методом `casefold()`. Регистр исходных заголовков виден в `SELECT *`.

| Вход | Правило |
| --- | --- |
| CSV | Первая непустая запись содержит имена столбцов. Число полей в строках должно совпадать с числом заголовков. Кавычки, разделители внутри кавычек и многострочные поля обрабатывает модуль `csv`. |
| Значения CSV | Пустое поле становится `NULL`, точные значения `true` и `false` становятся логическими. Числа распознаются по JSON-форме записи, например `-3`, `2.5` и `1e-2`. Остальное остаётся строкой, включая `001`, `null` и значения с внешними пробелами. |
| JSON | Верхний уровень представляет массив объектов с простыми значениями. Общий список столбцов — объединение имён свойств в порядке их первого появления. |
| Значения JSON | Поддерживаются строки, числа, логические значения и `null`. Отсутствующее свойство считается `NULL`. Поля с массивами и объектами вызывают ошибку. |
| Числа | Целые хранятся как `int`, вещественные как конечные `float`. Текст одного числа ограничен 256 символами. Дробные вычисления могут округляться. |

## Обработка запроса

- `WHERE` оставляет строки, для которых условие истинно. Сравнение с `NULL`
  даёт неопределённое значение. Для проверки пропуска используются
  `IS NULL` и `IS NOT NULL`.
- Приоритет убывает в порядке `NOT`, `AND`, `OR`. Операнды составных условий
  вычисляются, поэтому в каждой проверяемой части сравниваемые ненулевые
  значения должны иметь совместимые типы. Оба числовых типа совместимы.
- `GROUP BY` объединяет строки с одинаковыми значениями ключей. `NULL` в
  позиции ключа образует общую группу. В сгруппированной выборке обычные
  столбцы из `SELECT` должны присутствовать в `GROUP BY`. Сочетание
  `SELECT *` с `GROUP BY` вызывает ошибку.
- `COUNT(*)` считает строки, `COUNT(column)` считает заполненные значения.
  `SUM` и `AVG` обрабатывают числа. `MIN` и `MAX` работают со сравнимыми
  значениями одной категории. Все агрегаты с именем столбца пропускают
  `NULL`. Если значений нет, `COUNT` возвращает 0, остальные агрегаты
  возвращают `NULL`. Агрегаты без `GROUP BY` образуют одну общую группу.
- `AS` задаёт выходное имя. По умолчанию используется записанное имя
  столбца или имя агрегата в нижнем регистре. Имена результата уникальны.
  Для сортировки по имени агрегата без псевдонима укажите имя в двойных
  кавычках, например `ORDER BY "count"`.
- `ORDER BY` использует столбцы результата. Для `SELECT *` доступны все
  столбцы источника. По умолчанию применяется `ASC`, значения `NULL`
  идут последними в обоих направлениях. При равенстве ключей сохраняется
  исходный порядок строк или порядок первого появления групп.
- `LIMIT` ограничивает число строк после сортировки. Результат — массив
  объектов JSON.

Область реализации — выборка из одной таблицы. Соединения, подзапросы,
`HAVING`, арифметические выражения и команды изменения данных находятся
за пределами этой грамматики. SQL-файл ограничен 256 КиБ, запрос — 4096
значимыми лексемами и глубиной вложенных скобок и отрицаний 32.
При выполнении таблица целиком загружается в оперативную память.
